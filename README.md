# Rebeka Parental Control

Родительский контроль экранного времени с зачётом шагов.
Архитектура: **Device Admin + Accessibility Service + уведомление родителю**
(тот же принцип, что использует большинство коммерческих приложений —
Qustodio, Bark, Kaspersky Safe Kids). Это НЕ Device Owner: не требует сброса
телефона, ставится как обычное приложение.

## Что это даёт и чего не даёт (честно)

| Действие ребёнка | Результат |
|---|---|
| Смахнуть приложение из recents | Не помогает — блокировка работает через foreground-сервис |
| Settings → Приложения → Удалить | Кнопка "Удалить" неактивна, пока не сняты права администратора |
| Settings → Администраторы устройства → Деактивировать | **Технически возможно** — система не даёт стороннему приложению заблокировать это диалоговое окно. Accessibility Service детектирует открытие этого экрана и: (а) показывает предупреждение, (б) сразу шлёт пуш родителю |
| ADB (`adb shell pm uninstall`), root | Ничего не остановит — это выше уровня прав любого обычного приложения |

Итог: ребёнок технически подкованный и настойчивый может отключить.
Цель этой архитектуры — не физическая невозможность, а **задержка +
уведомление родителя**, что для семейного сценария обычно достаточно.
Если нужна гарантия уровня Family Link — см. предыдущее обсуждение про
Device Owner provisioning (отдельная, более тяжёлая задача, требует
сброса телефона).

## Стек и структура

Всё как в исходной архитектуре (Kotlin, Compose, Room, без ViewModel,
Repository как единственная точка доступа к данным) + новые пакеты:

```
data/            # StepEntry, UsageDay, AppSettings — Entity/Dao/Repository/Database
admin/           # DeviceAdminReceiver, PIN-логика для снятия прав
accessibility/   # BlockAccessibilityService — детект экрана "Администраторы устройства",
                 #   детект попытки Force Stop, показ предупреждения
usage/           # UsageStatsHelper — экранное время через UsageStatsManager
steps/           # StepCounterService — TYPE_STEP_COUNTER
blocking/        # BlockService (foreground) + оверлей блокировки экрана
notifications/   # ParentAlertNotifier — стаб отправки уведомления родителю
util/            # TimeLimitCalculator — лимит = 2ч + (шаги/5000)ч
ui/home/         # Compose-экран: шаги, оставшееся время, статус блокировки
navigation/      # Routes + NavHost
```

## Разрешения, которые нужно выдать вручную (не через диалог)

Это системные ограничения Android, обойти программно нельзя:

1. **Accessibility Service** — `Настройки → Спец. возможности → Rebeka → Вкл`.
   Родитель включает один раз при установке.
2. **Usage Access** (`PACKAGE_USAGE_STATS`) — `Настройки → Приложения →
   Особый доступ → Доступ к использованию`. Тоже вручную, диалог система
   не показывает.
3. **Device Admin** — стандартный системный диалог, приложение может его
   вызвать программно (`ACTION_ADD_DEVICE_ADMIN`).
4. **Разрешить оверлей поверх других приложений** (`SYSTEM_ALERT_WINDOW`) —
   с Android 6+ тоже отдельный экран настроек, не диалог.
5. **ACTIVITY_RECOGNITION** — обычный runtime-permission, диалог есть.

Без первых двух (Accessibility + Usage Access) приложение не сможет
ни считать экранное время, ни детектировать попытку отключения — стоит
сделать отдельный onboarding-экран, который проверяет каждое из них и
ведёт родителя в нужный системный экран (заготовка в `ui/home`).

## PIN родителя

PIN хранится хэшированным (SHA-256 + соль) в `AppSettings` через
DataStore/Room, не в открытом виде. Экран ввода PIN показывается перед:
- снятием блокировки раньше времени,
- изменением лимита (2 часа / 5000 шагов),
- открытием экрана "куда ведёт кнопка отключить админа" (см. `admin/AdminUtils.kt`).

## Сборка и CI

Тот же принцип, что в исходной архитектуре: `.github/workflows/build.yml`
собирает debug-APK на каждый push, release — только по ручному запуску
после того как заведены `RELEASE_KEYSTORE_*` секреты.

## Чеклист первого запуска

1. Склонировать репозиторий, открыть в Android Studio
2. Сгенерировать и закоммитить `debug.keystore` (команда — в исходной
   архитектуре, раздел "Ключи и доступы")
3. Собрать и установить на телефон ребёнка
4. Пройти onboarding: включить Accessibility, дать Usage Access, дать
   Device Admin, дать overlay-разрешение, разрешить ACTIVITY_RECOGNITION
5. Задать PIN родителя
6. Проверить: `adb shell dumpsys deviceidle` не должен убивать сервис
   (на некоторых прошивках — MIUI, ColorOS — нужно вручную отключить
   оптимизацию батареи для приложения, иначе foreground-сервис всё равно
   периодически убивается; это ограничение конкретных производителей,
   не самого Android)
